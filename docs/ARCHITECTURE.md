# Архитектура DaCode bootstrap

## Поток выполнения

```text
.dc source
   ↓
frontend.Lexer
   ↓ Token[]
frontend.Parser
   ↓
ast.Program
   ↓
runtime.Interpreter
   ↓
реальный результат программы
```

CLI и loader не содержат результатов программ. Они только находят `.dc`, читают текст, строят AST и передают его runtime.

## Слои

### `ast/`

Только описание структуры программы: выражения, инструкции, функции, классы, импорты. AST не знает про консоль, файлы, Python и ОС.

### `frontend/`

`tokens.py` задаёт Token, `lexer.py` превращает исходник в токены, `parser.py` превращает токены в AST. Новая грамматика должна в первую очередь жить здесь.

### `runtime/`

Содержит семантику DaCode:

- `environment.py` — контейнеры и правила `open()/close()`;
- `types.py` — проверка типов;
- `values.py` — `Void`, type markers, ссылки на файлы;
- `objects.py` — DaCode-объекты и классы;
- `control.py` — внутренние сигналы `return.back`, `straight`, `exit`;
- `interpreter.py` — сборка runtime и публичные точки расширения;
- `statements.py` — выполнение statements;
- `evaluator.py` — вычисление expressions;
- `functions.py` — пользовательские функции.

### `builtins/`

Стандартные команды не пришиты намертво к interpreter. Они устанавливаются через `BuiltinRegistry`.

Сейчас отдельно живут core-команды и файловые команды. Новый блок stdlib можно оформить отдельным installer-модулем.

### `bridges/`

Внешние языки подключаются через `BridgeRegistry`. Parser знает только синтаксис `from <source> import ...`, а конкретный adapter решает, как получить объект из Python/Java/и т.д.

Python bridge уже реализован. Остальные можно добавлять без переписывания lexer/parser.

### `loader/`

`discover_dc()` ищет runnable-файлы только по расширению `.dc`. Фиксированного имени `main.dc` не существует.

## Важные семантические решения

- Индексация списков и строк начинается с 1.
- `Void` — compound-значение и не может использоваться как условие или арифметический операнд.
- Нетипизированная переменная может сменить `Void` на прямое значение обычным присваиванием.
- `straight(error)` обрабатывает ошибку предыдущей инструкции.
- `return.back(expr) type` проверяет тип и завершает функцию.
- `first/twice` создаёт независимую копию значения между контейнерами, а не живую ссылку.
